# Technical Writer

## Job Description

### Mission
Own critical outcomes for Documentation to deliver Rebit commercial v1 in 6 months.

### Team
- Documentation

### Seniority
- Senior

### Hiring Priority
- P1

### Employment Type
- Full-time

### Scope of Work

#### Phase A (Months 1-2)
- Create architecture docs and workflow drafts

#### Phase B (Months 3-4)
- Publish SDK and feature documentation

#### Phase C (Months 5-6)
- Deliver launch docs, runbooks, and release notes

### Core Responsibilities
- Build and maintain high-quality documentation for users, SDK developers, and operators.
- Define documentation information architecture and publishing workflows.
- Partner with engineering and product to keep docs synchronized with releases.
- Create runnable examples, migration notes, and troubleshooting guidance.
- Own release notes and launch documentation completeness.

### Required Experience
- 6+ years production experience in relevant domain
- Demonstrated ability to deliver high-impact milestones under constrained timelines.
- Strong written design communication and technical decision discipline.

### Must-Have Skills
- Technical writing, API docs, information architecture

### Nice-to-Have Skills
- BIM/CAD docs experience

### Compensation and Location
- Target compensation: USD 180,000 to 360,000 base + equity
- Preferred hiring regions: US, UK, Germany, Netherlands, Canada
- Work mode: distributed with overlap for core team hours.

### Interview Process
1. Recruiter screen (30 min): motivation, communication, compensation alignment.
2. Hiring manager screen (60 min): role depth and ownership history.
3. Technical panel (2 x 60 min): architecture and execution quality.
4. Practical exercise (60 to 90 min): Cross-functional case study tied to v1 scope and developer adoption
5. Leadership or cross-functional round (45 min): collaboration and delivery behavior.
6. Final close (30 min): expectations, mission alignment, and offer readiness.

### Hiring Scorecard
- Technical communication clarity and accuracy: 35%
- Information architecture and doc usability: 25%
- Cross-functional execution and consistency: 20%
- API and tooling comprehension: 10%
- Editorial quality and maintainability: 10%

### Sourcing Strategy
- Priority target companies: Autodesk, Adobe, Figma, Stripe, Atlassian
- Community channels: Rust communities, domain-specific OSS maintainers, and conference speaker lists.
- Referral strategy: prioritize referrals from current principals and directors.

### 30/60/90-Day Outcomes
- First 30 days: complete onboarding, own first scoped deliverable, and contribute at least one design review.
- First 60 days: deliver one cross-team milestone and establish quality baselines in owned area.
- First 90 days: own a launch-critical stream with measurable reliability and performance outcomes.

### Collaboration Map
- Primary partners: adjacent domain teams, Platform, QA, Product.
- Review obligations: CODEOWNERS reviews and cross-domain API review.

### Success Metrics
- Scope delivered on phase timeline.
- Defect escape rate and reliability targets in owned area.
- Performance and build health for impacted crates.
- Documentation and handoff quality.

### Screening Questions
- How do you keep docs accurate in a rapidly changing codebase?
- Show an example where you improved developer onboarding through docs.
- What is your process for validating technical accuracy with engineers?

### Interview Focus
- Domain depth and system design judgment.
- Ability to ship under timeline and quality constraints.
- Cross-functional communication and ownership behavior.
